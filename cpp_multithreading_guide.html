C++ 现代多线程与并发编程笔记

整理自 ROS 2 / C++ 模拟实战，聚焦核心机理、典型避坑点与高频模式。去除了多余装饰，以紧凑高效的文档形式呈现。

1. 多线程核心概念

1.1 解决什么问题

单线程程序如同一个人干活，遇到耗时操作（IO读写、网络通信、复杂运算）时，整个主流程会被完全阻塞。多线程的核心意义在于重叠等待时间，使 CPU 能够并发处理不同任务。

1.2 典型场景对比

应用场景 单线程表现 多线程并发表现
UI / ROS 回调响应 处理长耗时任务时，界面冻结，ROS 话题无法及时接收新消息并引发队列溢出。 主线程继续快速接收数据并刷新，耗时检测或计算派发给后台工作线程处理。
批量数据计算 1000 个任务依次串行处理，只能利用单核 CPU。 分摊至 4 个线程并发执行，多核打满，耗时成倍降低。

2. std::thread 基础

2.1 线程创建与传参

创建线程即调用 std::thread 构造函数。参数默认以值拷贝形式传递到线程私有空间：

// 普通函数作为线程入口
void worker(int a, int b);
std::thread t1(worker, 10, 20);

// 类成员函数作为线程入口
std::thread t2(&MyClass::memberFunc, this, arg1, arg2);

2.2 join 与 detach

⚠️ 核心规则： std::thread 对象析构时，如果内部线程仍然处于可结合状态（joinable）但未被处理，C++ 运行时会直接调用 std::terminate() 强退程序。
  • t.join()：主线程阻塞等待子线程执行完毕，回收其系统资源。
  • t.detach()：将子线程与主线程剥离，成为后台守护线程自生自灭（需确保后台线程访问的数据不会提前析构）。

2.3 Lambda 传参剖析

在 ROS 2 等类设计中，最常用的线程调用方式是 Lambda：

int cur = temp_now;
int prev = temp_privious;
std::thread t([this, cur, prev]() {
    this->checkSpeedChange(cur, prev);
});
t.join();
结构 作用 记忆口诀与注意事项
[ ] 捕获列表 指定外部作用域哪些变量被引入匿名函数 从外面拿东西。捕获 this 可访问类方法；捕获变量拷贝值避免外部修改。
( ) 参数列表 线程启动时传入的参数 别人传给你。通常为空 ()，因为需要的数据已在捕获列表中准备就绪。
{ } 函数体 实际执行逻辑 开始干活。调用具体的处理函数。
💡 为什么需要 int cur = temp_now; 做一次值拷贝？
这是防御性编程。成员变量随时可能被下一次回调修改，通过值拷贝拍下“数据快照”，子线程即使因为调度延后执行，读取的也是触发那一刻的历史真值。

3. 锁与安全保护 (std::mutex)

3.1 为什么会数据竞争

对共享变量的非原子操作（如 counter++ 或容器 push_back），在汇编层面包含 读(LOAD) -> 改(ADD) -> 写(STORE) 三步。并发执行时步骤交错，导致部分写入被覆盖丢失，甚至破坏容器内部结构引发 Segmentation Fault。

3.2 lock_guard 机制与生命周期

std::lock_guard 采用 RAII（资源获取即初始化）模式：构造时自动 lock()，析构时自动 unlock()。杜绝因忘记手动解锁或中途 return / 抛异常导致的永久死锁。

3.3 缩小临界区技巧

lock_guard 的作用域精确绑定在它所在的大括号 { } 范围。工程中提倡“锁保护区间越小越好”：

void onMessageReceived() {
    int processed_val = heavyCalculation(); // 1. 耗时计算在锁外执行

    {
        std::lock_guard<std::mutex> lock(mtx); // 2. 手动加大括号，上锁
        shared_history.push_back(processed_val);
    } // 3. 刚出大括号，立刻自动解锁！

    sendLogOverNetwork(); // 4. 耗时网络发送在锁外，不阻塞其他线程
}

4. 并发四大典型缺陷

4.1 死锁与避免

多个线程按不同顺序请求多把锁，互相等待对方释放资源。例如 A 持有 mtx1 请求 mtx2，B 持有 mtx2 请求 mtx1。

  • 规则：所有线程必须遵循严格一致的加锁顺序（如始终先锁 1 再锁 2）。
  • 现代 C++ 方案：使用 C++17 提供的 std::scoped_lock lock(mtx1, mtx2);，内部采用死锁避免算法一次性原子锁住全部锁。

4.2 传引用陷阱：std::ref

std::thread 构造函数默认对所有参数进行拷贝。如果线程函数接收引用参数 void func(int& val)，必须显式用 std::ref(val) 包裹，否则编译期报错或只修改临时副本。

5. 极简口诀与速查表

组件 / 概念 核心职责 高频规范
std::thread 创建并管理线程 对象析构前必须执行 join() 或 detach()。
std::mutex 互斥实体 禁止手动裸调 lock/unlock，优先使用管理器。
std::lock_guard RAII 自动锁 生于声明处，死于右括号；善用 { } 缩小临界区。
std::scoped_lock C++17 多锁管理 一次性安全锁多把互斥锁，原生防御死锁。
std::ref 线程引用传递 将变量以真实引用传递给线程目标函数。

没锁就竞争，有锁就排队；手动锁怕忘，guard 帮你扛；
生于声明处，死于右括号；要想早解锁，大括号来缩。
